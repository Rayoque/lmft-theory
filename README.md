# LMFT Theory Study Pipeline

A single-page study tool for the **California LMFT Clinical Exam (LMCE)**, built
from five .docx packets. Theory content only.

**The app:** `index.html` — one file, vanilla JS, no build step, no dependencies,
no login. Works offline after first load because the data is inlined at build
time rather than fetched.

---

## The one rule this repo is built around

**Nothing in the item bank comes from outside the five packets in `/source`.**

That isn't a promise, it's an architecture. `theories.json` is generated by
resolving *block indices* into the extracted source — no fact text is ever
typed by hand — so a `sourceLine` is structurally incapable of containing words
that are not in the packet. Item options are then assembled only from those
fact objects. There is no code path that writes option text from anything else.

If a fact is not in the packet, it does not exist here. Blank cells in the grid
are blank in her packet.

## Numbers, honestly

| | |
|---|---|
| Discrete facts extracted | **366** across 14 models |
| Items generated | **392** |
| Killed by verification | **36 (9.2%)** |
| Passed all gates | 356 |
| **Shipped in the app** | **200** (60 Tier 1 / 90 Tier 2 / 50 Tier 3) |

The 356 → 200 step is **selection, not killing.** The brief caps the bank
deliberately: the corpus is ~366 facts, she has 8 days, and a tool that serves
356 items pretends otherwise. Selection prefers blind-graded items and
round-robins across models so no model is crowded out.

### Where the kill rate came from

| Gate | Killed | |
|---|---|---|
| 1 · blind re-answer | 9 | grader flagged 2+ defensible answers |
| 2 · uniqueness | 9 | keyed answer shared by >1 model |
| 4 · distractor validity | 17 | distractor arguably correct, or restates the key |
| 5 · source integrity | 1 | quoted a corrupted packet line |

**Read this before trusting the number.** The brief expects 10–25% and warns
that below 5% means the verifier is broken. Deterministic gates alone came in
at 4.1%, and that is explainable rather than alarming: gate 3 (traceability) is
*unfailable by construction* here, because options are assembled from
`theories.json` objects rather than written freely. The brief's 10–25%
expectation assumes free-form generation, where invented sourceLines are the
common failure. The real signal came from gate 1.

### What gate 1 actually covered

Blind re-answer ran as a separate pass: batches carrying only a stem and
shuffled options — no key, no rationale, no `belongsTo`, no `sourceLine` —
answered by fresh graders given the five packets and told to answer strictly
from them.

It ran twice. The first pass exposed real item ids, which encode the model
(`t1_bowen_role_supervisor`); a grader flagged that as leaking the answer. The
second pass re-ran the highest-risk items with **opaque ids** (`q001`…), so the
grader had nothing but the stem and the options.

**150 of the 200 shipped items (75%) were blind-graded**, including *every*
item of every type except `T3_concept`:

| Type | Graded | |
|---|---|---|
| `T2_collision` | 62/62 | the tool's core purpose |
| `T1_phase` | 46/46 | the domain she named as most important |
| `V_vignette` | 17/17 | hand-authored |
| `T2_examtip` | 11/11 | the instructor's own flagged content |
| `T1_change` | 9/9 | |
| `T1_marker` | 5/5 | |
| `T3_concept` | 0/50 | verbatim definition matching, lowest risk |

**Across all 150, no grader ever disagreed with the answer key.** Every gate-1
kill is an item a grader answered correctly but flagged as having two
defensible options. The keys are sound; ambiguity was the real defect, and
the second pass — with the id confound removed — found none remaining.

## Judgement calls worth knowing about

**Satir is dual-tagged `["systems","humanistic"]`.** The brief only asks for
Experiential to be dual-tagged, but Satir's own theory-of-change line ends
"Humanistic approach." That is in the source, not inferred.

**"Supervisor" is unique to Bowen.** It was initially lumped into the
coach/consultant collision class. Solution-Focused's source says only
"Therapist is a consultant, coach" — it never says supervisor, and the brief's
table lists the collision as "Coach / consultant". Corrected, and it is now a
legal inverse-item answer.

**Some collision classes group a shared *function* without marking the named
techniques ambiguous.** Bowen's genogram, Satir's family life chronology,
Structural's family map and Experiential's trial of labor all map family
history, but each has its own proper name. Without this distinction the four
markers the brief confirms as unique were being wrongly killed.

**`intraModel` items exist.** Term↔definition items and the packet's own
disambiguations (the psychodynamic four-way; behavioural experiment vs
exposure; three-column vs thought record) use same-model distractors on
purpose — the stem's verbatim definition is the disambiguator, not the model
name. Gate 4 honours the flag; gate 1 is what actually checks them.

## Schema exceptions (brief §3), all preserved

- **CBT** — `changeMechanism`, `therapistRoles` and `goals` are all `null`. The
  source is an intervention catalogue (23 techniques) plus phases. Nothing
  synthesised. It carries 7 exam tips, the most of any model.
- **Client Centered** — `phases: null`, and the packet's own warning survives
  intact as an `examTip`: the exam may still ask about initial or middle stage,
  and the answer shape is unconditional positive regard, empathy, therapist
  congruence, promotion of self-acceptance. The app shows this in place of
  phases rather than hiding the gap.
- **Experiential/Symbolic** — `["humanistic","systems"]`, so it appears in
  family-vignette practice despite living in the Humanistic file. Its two
  ready-made vignettes (mother and child → include the whole family; silent
  family → wait silently) are in the bank with their stated answers.

## Using it

**Learn** is the default and the acquisition loop: read the brief, then answer
three questions on that model immediately, before leaving it. **Drill** mixes
models with the collision set weighted heavy. **Vignette** unlocks once all 14
models have been opened in Learn.

Two things that will look like bugs and are not:

1. **Accuracy in Drill will look worse than it feels like it should.** Items are
   deliberately interleaved — never two in a row from the same model. Blocked
   practice feels more productive and produces worse discrimination, which is
   exactly the failure mode here. The target band is 70–80%. The app says so
   on the session summary rather than letting a low number read as a verdict.
2. **Missed items come back, and confident misses come back twice as often.**
   Answering "knew it" and being wrong is the most dangerous state on the
   board — it is the collision trap, where a familiar word fires before you
   check. Items retire at 3 correct across 3 *distinct calendar days*.

**Every reveal shows the verbatim source line from the packet.** If an item
looks wrong, the packet wins. That is the point — she should be able to catch a
bad item rather than memorise it.

## Scope

**Theory only.** The LMCE spans several content domains; this covers one. A
green dashboard here does not mean she is ready for the exam, and the app says
so on every session summary.

This repo is public in order to serve GitHub Pages, which means the packet
excerpts in `theories.json` and the item bank are publicly readable.

## Rebuilding

```bash
python scripts/extract.py          # .docx -> extracted/ (keeps bold + tables)
python scripts/build_theories.py   # -> theories.json   (366 facts)
python scripts/build_collisions.py # -> collisions.json (gates generation)
python scripts/generate_items.py   # -> items_raw.json
python scripts/verify.py           # gates 2-4 -> kill_log.json
python scripts/blind_pass.py export        # -> blind/batch_*.json
#   grade each batch with a fresh context, write blind/answers_NN.json
python scripts/blind_pass.py ingest        # gate 1
python scripts/polish.py           # grader-found defects
python scripts/select.py           # -> items.json (the 200)
python scripts/build_app.py        # -> index.html
node /tmp/apptest.js               # queue + mastery invariants
```

Order is load-bearing. Collisions gate generation; generation gates the app.
